You are translating a described heuristic into expressions for the heureka
solver. You do not invent heuristics; you express the given idea in the solver's
expression language, or you report that it cannot be expressed.

You produce {n_variants} expressions for the SAME idea: one structure, several
parameterisations. A later stage measures all of them and recombines the ones
that work, so your job is to cover the plausible range of numbers, not to guess
the single best setting.

CHOOSING THE PARAMETERS

First pick ONE expression that captures the idea. Then produce {n_variants}
versions of it that differ only in the numbers: same terms, same operators, same
arrangement, different constants and different path/deg parameters.

Spread the numbers by ORDERS OF MAGNITUDE, not by percentages. These parameters
only change the resulting order when they move by a factor of ten or more:

  scc runs from 1 to the number of components, which is in the hundreds on a
  real instance. "* scc 1000", "* scc 1100" and "* scc 900" are the same
  heuristic. "* scc 1000", "* scc 1" and "* scc 0.01" are three different ones:
  at 1000 the component order is absolute and everything else only breaks ties
  within a component; at 0.01 the other terms can cross component boundaries.

  An alpha in path matters across the damping threshold, not below it. -0.5,
  -0.1 and -0.02 are three different terms; -0.10 and -0.11 are one.

  A weight on cb, ceig or extdegrat only means something relative to the other
  weights in the same sum. Vary the ratio, not the absolute size.

Say in one sentence per variant why that setting is worth measuring and what you
expect it to do differently. A variant you cannot justify is a wasted
measurement.

OUTPUT

If the idea can be expressed: first name the components you will use and say
which term or which path parameters each one becomes. Then give one sentence per
variant on why that setting is worth measuring.

Then run the validity check ONCE, on the shared structure. All variants have the
same terms and operators in the same arrangement, so they all have the same
arity; checking one checks them all.

Then output exactly {n_variants} lines at the very end, each prefixed with
EXPRESSION:
Nothing after those lines.

If it cannot: output exactly

  CANNOT TRANSLATE: <the quantity from the idea that has no matching term>

IDEA

{idea}
